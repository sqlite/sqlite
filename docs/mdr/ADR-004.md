# ADR-004: MDR as Adaptive, Lossless Archival Compression for SQLite

Status: accepted (MDR-004)
Date: 2026-10-29
Branch: mdr/research
Supersedes aspects of: ADR-001 (which stays in force for the MDR1 format)

## Decision

> MDR is an adaptive, lossless archival compression system for SQLite.
> Mathematical dimensionality is a candidate representation technique, not an
> architectural requirement. Codec promotion depends on exact reconstruction,
> complete wire-size accounting, and advantages demonstrated on independent
> workloads.

## Evidence base

- MDR-001 (d17dcaab4): MDR1 archive contract, byte-exact roundtrip,
  integrity_check preserved, random-data control honest.
- MDR-002 (5553cec41): 5D fold (8^5 digit-reversal tiles) beats zstd on
  structured fixtures, but 14/23 regress; gains inflate via one fixture.
- MDR-003 (bdfef3045): attribution gate. On held-out fixtures the fold wins
  0/8 against conventional byte-shuffle (D1) — the "5D" advantage over plain
  reordering is not demonstrated. Adaptive selection (exhaustive argmin,
  charged metadata) verified exact and picks fold never. Negative result for
  promoting fold; positive for the portfolio architecture.
- MDR-004: `mdr/tools/mdrc.py` implements MDR2 archive: per-segment
  adaptive portfolio {stored, zstd, D1(4/16), D2 bit, D3 page-aware}.

## Frozen portfolio (MDR2 selector)

| id | codec        | role                                |
|----|--------------|-------------------------------------|
| 0  | stored       | guaranteed no-expansion fallback    |
| 1  | zstd         | raw bytes                           |
| 2k | D1, stride k | structured-data layout (k in 4,16)  |
| 3  | D2           | bit shuffle (retained from MDR-002) |
| 4  | D3           | SQLite page-aware header/payload    |

The 5D fold is excluded from the selector; it stays in the MDR-002/003
experimental suite. Promotion requires new held-out evidence.

## Restore contracts (both supported, both marked in the header)

- byte-exact: pack reads source bytes; unpack reproduces them exactly
  (sha256 in footer).
- backup: `mdrc pack --backup` captures a consistent snapshot via the
  SQLite online backup API. The snapshot is a valid database state; it need
  not equal a separately captured raw file byte-for-byte.

## Durability and robustness

- Footer written last, after fsync: a failed write never presents as
  complete (accepted: incomplete ⇒ no "M2DN" footer ⇒ unpack rejects).
- Every segment: codec id, param, length, CRC-32. Unpacker rejects
  wrong magic/version, unknown codecs, truncation, CRC mismatch, segment
  overrun, header/footer mismatch, oversized src_len claims.

## Evidence for promotion gate (GA1-GA8, benchmarks/mdr/mdr004_acceptance.py)

Measured on fresh held-out fleet (11 cases, 3 size classes, 6 types):
GA1 byte-exact all; GA2 integrity_check + sample queries all ok;
GA4 45.2% saving vs zstd-19 end-to-end on the fleet; GA6 all 9 tamper
cases rejected; GA5 resources reported per run. 40% is a target, not a
pass/fail bar; no gain claimed without fresh measurement (GA8).
